## credentials 表

```go
type Credential struct {
    ID          string    `gorm:"primaryKey;size:36"`
    Name        string    `gorm:"size:100;not null;uniqueIndex"`
    Description string    `gorm:"size:255"`

}
```

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | varchar(36) | PK | UUID |
| name | varchar(100) | NOT NULL, UNIQUE | 凭据名称 |
| description | varchar(255) | | 描述 |
| username | varchar(100) | NOT NULL | 用户名 |
| password | varchar(255) | NOT NULL | 加密密码 |
| created_at | datetime | | 创建时间 |
| updated_at | datetime | | 更新时间 |

| 字段 | 类型 | 约束 | 说明 |

**认证方式**：
- 方式一：通过 `credential_id` 关联凭据表
- 方式二：直接指定 `username` + `password`

## sync_tasks 表

```go
type SyncTask struct {
    ID          string `gorm:"primaryKey;size:36"`
    Name        string `gorm:"size:100;not null"`
    Remark      string `gorm:"size:500"`
    SourceID    string `gorm:"size:36;index"`
    TargetID    string `gorm:"size:36;index"`          // 兼容第一个目标
    SourceType  string `gorm:"size:20;not null"`        // mysql/elasticsearch
    TargetType  string `gorm:"size:20;not null"`
    Config      string `gorm:"type:text;not null"`      // JSON 配置
    Status      string `gorm:"size:20;not null;default:idle;index"`
    IsRunning   bool   `gorm:"not null;default:false;index"`
    SyncMode    string `gorm:"size:20;not null;default:full"` // full/incremental
    CurrentStep string `gorm:"size:50;default:''"`
    QueueType   string `gorm:"size:20;default:memory"`        // memory/redis

    // 增量同步字段
    IncrementalEnabled       bool   `gorm:"default:false"`
    SnapshotBinlogFile       string `gorm:"size:100"`
    SnapshotBinlogPos        uint32 `gorm:"default:0"`
    CurrentBinlogFile        string `gorm:"size:100"`
    CurrentBinlogPos         uint32 `gorm:"default:0"`
    FullSyncCompleted        bool   `gorm:"default:false"`
    IncrementalLag           int    `gorm:"default:0"`
    IncrementalEventsTotal   int64  `gorm:"default:0"`
    IncrementalEventsApplied int64  `gorm:"default:0"`

    CreatedAt time.Time
    UpdatedAt time.Time
}
```

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | varchar(36) | PK | UUID |
| name | varchar(100) | NOT NULL | 任务名称 |
| remark | varchar(500) | | 备注 |
| source_id | varchar(36) | INDEX | 源数据源 ID |
| target_id | varchar(36) | INDEX | 第一个目标 ID（兼容） |
| source_type | varchar(20) | NOT NULL | 源类型 |
| target_type | varchar(20) | NOT NULL | 目标类型 |
| config | text | NOT NULL | JSON 格式任务配置 |

| sync_mode | varchar(20) | NOT NULL, DEFAULT 'full' | full/incremental |
| current_step | varchar(50) | DEFAULT '' | 当前步骤 |
| queue_type | varchar(20) | DEFAULT 'memory' | 队列类型 |
| incremental_enabled | bool | DEFAULT false | 启用增量 |
| snapshot_binlog_file | varchar(100) | | 快照 Binlog 文件 |
| snapshot_binlog_pos | uint32 | DEFAULT 0 | 快照 Binlog 位置 |
| current_binlog_file | varchar(100) | | 当前 Binlog 文件 |
| current_binlog_pos | uint32 | DEFAULT 0 | 当前 Binlog 位置 |
| full_sync_completed | bool | DEFAULT false | 全量完成标记 |
| incremental_lag | int | DEFAULT 0 | 增量延迟（秒） |
| incremental_events_total | int64 | DEFAULT 0 | 事件总数 |
| incremental_events_applied | int64 | DEFAULT 0 | 已应用事件数 |
| created_at | datetime | | 创建时间 |
| updated_at | datetime | | 更新时间 |

## 关系图

```
credentials (1) ←── (N) data_sources
                        ↑
                        │ credential_id (可选)
                        
data_sources (1) ←── (N) sync_tasks (source_id)
data_sources (1) ←── (N) sync_tasks (target_id, 兼容)
data_sources (1) ←── (N) task_target_sources (target_id)

sync_tasks (1) ←── (N) task_target_sources (task_id)
```

**注意**：不使用 GORM 外键约束（`constraint:-`），通过 ID 字段维护关系。

# 数据库设计

## 📋 文档说明

本文档详细描述 DataTrac 系统的数据库设计，包括表结构、关系和索引。

**文档版本**: v1.0  
**最后更新**: 2026-01-30  
**数据库**: SQLite

---

## 🎯 概述

DataTrac 使用 SQLite 作为元数据存储，管理数据源、任务配置和任务执行状态。

**核心表**:
- `data_sources` - 数据源表
- `sync_tasks` - 任务主表
- `task_unit_configs` - 任务单元配置表
- `task_unit_runtimes` - 任务单元运行记录表

---

## 📊 表结构设计

### 1. data_sources - 数据源表

**用途**: 存储 MySQL 和 Elasticsearch 数据源信息

```sql
CREATE TABLE data_sources (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    type TEXT NOT NULL,              -- 'mysql' 或 'elasticsearch'
    host TEXT NOT NULL,
    port INTEGER NOT NULL,
    username TEXT NOT NULL,
    password TEXT NOT NULL,          -- AES-256-GCM 加密
    database_name TEXT,              -- MySQL 专用
    created_at INTEGER NOT NULL,     -- 毫秒时间戳
    updated_at INTEGER NOT NULL      -- 毫秒时间戳
);

CREATE INDEX idx_data_sources_type ON data_sources(type);
CREATE INDEX idx_data_sources_name ON data_sources(name);
```

**字段说明**:
- `id`: UUID 主键
- `type`: 数据源类型（mysql/elasticsearch）
- `password`: 使用 AES-256-GCM 加密存储
- `database_name`: MySQL 的默认数据库（可选）

---

### 2. sync_tasks - 任务主表

**用途**: 存储同步任务的基本信息和配置

```sql
CREATE TABLE sync_tasks (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    source_id TEXT NOT NULL,         -- 关联 data_sources.id
    target_id TEXT NOT NULL,         -- 关联 data_sources.id
    source_type TEXT NOT NULL,       -- 'mysql' 或 'elasticsearch'
    target_type TEXT NOT NULL,       -- 'mysql' 或 'elasticsearch'
    config TEXT NOT NULL,            -- JSON 格式的任务配置
    status TEXT NOT NULL,            -- 'idle', 'running', 'paused', 'completed', 'failed'
    sync_mode TEXT NOT NULL DEFAULT 'auto',  -- 同步模式（目前仅支持 'auto'）
    created_at INTEGER NOT NULL,     -- 毫秒时间戳
    updated_at INTEGER NOT NULL,     -- 毫秒时间戳
    FOREIGN KEY (source_id) REFERENCES data_sources(id) ON DELETE CASCADE,
    FOREIGN KEY (target_id) REFERENCES data_sources(id) ON DELETE CASCADE
);

CREATE INDEX idx_sync_tasks_status ON sync_tasks(status);
CREATE INDEX idx_sync_tasks_source_id ON sync_tasks(source_id);
CREATE INDEX idx_sync_tasks_target_id ON sync_tasks(target_id);
```

**字段说明**:
- `config`: JSON 格式，包含 mysqlConfig、esConfig、syncConfig
- `sync_mode`: 同步模式，目前仅支持 'auto'（自动模式）
- `status`: 任务状态

**config JSON 结构**:
```json
{
  "mysqlConfig": {
    "databases": [
      {
        "database": "db1",
        "tables": ["table1", "table2"]
      }
    ]
  },
  "esConfig": {
    "selectedIndices": ["index1", "index2"]
  },
  "syncConfig": {
    "batchSize": 2500,
    "threadCount": 4,
    "errorStrategy": "skip",
    "tableExistsStrategy": "drop"
  }
}
```

---

### 3. task_unit_configs - 任务单元配置表 ⭐

**用途**: 存储任务要同步的表/索引列表（从任务配置中提取）

```sql
CREATE TABLE task_unit_configs (
    id TEXT PRIMARY KEY,
    task_id TEXT NOT NULL,
    unit_name TEXT NOT NULL,         -- 表名或索引名
    unit_type TEXT NOT NULL,         -- 'table' 或 'index'
    created_at INTEGER NOT NULL,     -- 毫秒时间戳
    FOREIGN KEY (task_id) REFERENCES sync_tasks(id) ON DELETE CASCADE,
    UNIQUE(task_id, unit_name)       -- 同一任务中单元名称唯一
);

CREATE INDEX idx_task_unit_configs_task_id ON task_unit_configs(task_id);
CREATE INDEX idx_task_unit_configs_unit_type ON task_unit_configs(unit_type);
```

**字段说明**:
- `unit_name`: 表名（如 "db1.table1"）或索引名（如 "index-a"）
- `unit_type`: 单元类型（table/index）
- `UNIQUE(task_id, unit_name)`: 确保同一任务中单元名称唯一

**数据来源**:
- MySQL: 从 `config.mysqlConfig.databases[].tables` 提取
- ES: 从 `config.esConfig.selectedIndices` 提取

---

### 4. task_unit_runtimes - 任务单元运行记录表 ⭐

**用途**: 存储任务单元的执行状态和进度（支持断点续传）

```sql
CREATE TABLE task_unit_runtimes (
    id TEXT PRIMARY KEY,
    task_id TEXT NOT NULL,
    unit_name TEXT NOT NULL,         -- 表名或索引名
    status TEXT NOT NULL,            -- 'pending', 'running', 'completed', 'failed', 'paused'
    total_records INTEGER DEFAULT 0,
    processed_records INTEGER DEFAULT 0,
    error_message TEXT,              -- 错误信息（失败时）
    started_at INTEGER,              -- 开始时间（毫秒时间戳）
    updated_at INTEGER NOT NULL,     -- 更新时间（毫秒时间戳）
    last_processed_batch INTEGER,    -- 最后处理的批次号（预留）
    FOREIGN KEY (task_id) REFERENCES sync_tasks(id) ON DELETE CASCADE,
    UNIQUE(task_id, unit_name)       -- 同一任务中单元名称唯一
);

CREATE INDEX idx_task_unit_runtimes_task_id ON task_unit_runtimes(task_id);
CREATE INDEX idx_task_unit_runtimes_status ON task_unit_runtimes(status);
CREATE INDEX idx_task_unit_runtimes_task_status ON task_unit_runtimes(task_id, status);
```

**字段说明**:
- `unit_name`: 与 task_unit_configs.unit_name 对应
- `status`: 执行状态
- `total_records`: 总记录数（同步开始时获取）
- `processed_records`: 已处理记录数（实时更新）
- `last_processed_batch`: 最后处理的批次号（预留，用于未来的记录级断点续传）

**状态流转**:
```
pending → running → completed
                 ↘ failed
                 ↘ paused
```

## 🔗 表关系图

```
┌─────────────────────┐
│   data_sources      │
│  (数据源表)          │
└─────────────────────┘
         ↑ ↑
         │ │ (source_id, target_id)
         │ │
┌─────────────────────┐
│   sync_tasks        │
│  (任务主表)          │
└─────────────────────┘
         │
         │ (task_id)
         ↓
┌─────────────────────┐
│ task_unit_configs   │
│ (任务单元配置表)     │
└─────────────────────┘
         │
         │ (task_id + unit_name)
         ↓
┌─────────────────────┐
│ task_unit_runtimes  │
│ (任务单元运行记录表) │
└─────────────────────┘
```

**关系说明**:
- `data_sources` ← `sync_tasks`: 1:N（一个数据源可以被多个任务使用）
- `sync_tasks` → `task_unit_configs`: 1:N（一个任务包含多个单元配置）
- `task_unit_configs` → `task_unit_runtimes`: 1:1（一个配置对应一个运行记录）

## 🔄 三表结构工作流程

### 1. 任务创建

```
用户创建任务
   ↓
保存到 sync_tasks 表
   ↓
从 config 提取单元列表
   ↓
保存到 task_unit_configs 表
```

### 2. 任务启动（首次）

```
用户启动任务
   ↓
TaskLoader::init_task_units
   ↓
从 task_unit_configs 读取单元列表
   ↓
为每个单元创建运行记录
   ↓
保存到 task_unit_runtimes 表（status = pending）
```

### 3. 任务执行

```
TaskManager::execute_auto_mode
   ↓
从 task_unit_runtimes 加载单元
   ↓
过滤未完成单元（status != completed）
   ↓
并发执行
   ├─ 更新 status = running
   ├─ 更新 processed_records
   └─ 更新 status = completed/failed
```

### 4. 任务重启（断点续传）

```
用户重启任务
   ↓
TaskLoader::init_task_units
   ↓
从 task_unit_configs 读取单元列表
   ↓
加载现有的 task_unit_runtimes
   ↓
对比配置和运行记录
   ├─ 已完成 → 保持 completed
   ├─ 运行中 → 重置为 pending
   └─ 失败 → 保持 failed
   ↓
清理孤立的运行记录
```

## 📝 数据操作示例

### 创建任务

```rust
// 1. 保存任务主表
let task = SyncTask {
    id: uuid::Uuid::new_v4().to_string(),
    name: "MySQL to ES Sync".to_string(),
    source_id: "source-123".to_string(),
    target_id: "target-456".to_string(),
    source_type: DataSourceType::Mysql,
    target_type: DataSourceType::Elasticsearch,
    config: serde_json::to_string(&config)?,
    status: TaskStatus::Idle,
    sync_mode: "auto".to_string(),
    created_at: now,
    updated_at: now,
};
storage.save_task(&task).await?;

// 2. 提取并保存单元配置
let unit_configs = extract_unit_configs(&config);
for unit_config in unit_configs {
    storage.save_unit_config(&unit_config).await?;
}
```

### 初始化任务单元

```rust
// 从配置表读取
let configs = storage.load_unit_configs(task_id).await?;

// 加载现有运行记录
let existing_runtimes = storage.load_unit_runtimes(task_id).await?;

// 创建或更新运行记录
for config in configs {
    if let Some(existing) = find_runtime(&existing_runtimes, &config.unit_name) {
        // 已有记录，根据状态处理
        if existing.status == TaskUnitStatus::Running {
            // 重置为 pending
            storage.reset_runtime(task_id, &config.unit_name).await?;
        }
    } else {
        // 创建新记录
        let runtime = TaskUnitRuntime {
            id: uuid::Uuid::new_v4().to_string(),
            task_id: task_id.to_string(),
            unit_name: config.unit_name.clone(),
            status: TaskUnitStatus::Pending,
            total_records: 0,
            processed_records: 0,
            error_message: None,
            started_at: None,
            updated_at: now,
            last_processed_batch: None,
        };
        storage.save_unit_runtime(&runtime).await?;
    }
}
```

### 更新进度

```rust
// 更新运行记录
storage.update_runtime_progress(
    task_id,
    unit_name,
    total_records,
    processed_records
).await?;
```

## 🎯 设计优势

### 1. 配置与运行分离
- `task_unit_configs`: 存储配置（不变）
- `task_unit_runtimes`: 存储运行状态（可变）
- 支持重置运行记录而不影响配置

### 2. 断点续传支持
- 运行记录持久化到数据库
- 支持任务暂停、恢复、重启
- 已完成单元不重复执行

### 3. 数据一致性
- 外键约束保证引用完整性
- 唯一约束防止重复数据
- 级联删除自动清理关联数据

### 4. 查询性能
- 合理的索引设计
- 支持高效的状态过滤
- 支持快速的关联查询

## 🔍 常用查询

### 查询任务的所有单元

```sql
SELECT 
    c.unit_name,
    c.unit_type,
    r.status,
    r.total_records,
    r.processed_records
FROM task_unit_configs c
LEFT JOIN task_unit_runtimes r ON c.task_id = r.task_id AND c.unit_name = r.unit_name
WHERE c.task_id = ?
ORDER BY c.unit_name;
```

### 查询未完成的单元

```sql
SELECT * FROM task_unit_runtimes
WHERE task_id = ? AND status != 'completed'
ORDER BY unit_name;
```

### 查询失败的单元

```sql
SELECT * FROM task_unit_runtimes
WHERE task_id = ? AND status = 'failed'
ORDER BY unit_name;
```

### 统计任务进度

```sql
SELECT 
    COUNT(*) as total,
    SUM(CASE WHEN status = 'completed' THEN 1 ELSE 0 END) as completed,
    SUM(CASE WHEN status = 'running' THEN 1 ELSE 0 END) as running,
    SUM(CASE WHEN status = 'failed' THEN 1 ELSE 0 END) as failed,
    SUM(CASE WHEN status = 'pending' THEN 1 ELSE 0 END) as pending
FROM task_unit_runtimes
WHERE task_id = ?;
```
