# 增量同步调试指南

## 概述

当增量同步任务出现问题时，可通过以下方法快速定位。

---

## 日志排查

### 任务日志

```
GET /api/v1/tasks/:id/logs?since=2026-07-06T00:00:00Z
```

日志分类：
- `incremental` — 增量同步操作
- `binlog` — Binlog 监听事件
- `error` — 错误信息

### 文件日志

```
logs/tasks/{taskID}.log
```

格式：`时间\t级别\t分类\t内容`

---

## 状态检查

### 表状态

```
GET /api/v1/tasks/:id/table-status
```

返回：`{ "table_name": "pending|syncing|completed|failed" }`

### 步骤状态

```
GET /api/v1/tasks/:id/step-status
```

### 增量统计

SSE Topic：`task:{id}:incremental`

包含：`events_total`、`events_applied`、`lag`（秒）

---

## 常见问题

| 问题 | 排查方向 |
|---|---|
| 增量不启动 | 检查 binlog_format=ROW |
| 延迟增大 | 检查目标库写入性能 |
| 事件丢失 | 检查 Queue 长度和 Consumer 状态 |
| 断点失效 | 检查 sync_tasks 表 Binlog 位点字段 |
# 增量同步调试指南

## 概述

当增量同步任务出现问题时，可以使用以下调试工具来快速定位问题原因。

## 调试API接口

### 1. 诊断增量同步

**接口**: `POST /api/v1/debug/incremental/{taskId}/diagnose`

**功能**: 全面诊断增量同步任务的配置和状态

**使用方法**:
```bash
curl -X POST http://localhost:8080/api/v1/debug/incremental/{taskId}/diagnose
```

**检查项目**:
- 任务配置是否正确
- 源库binlog配置是否符合要求
- 队列状态是否正常
- 增量同步实例是否运行

### 2. 测试binlog监听器

**接口**: `POST /api/v1/debug/incremental/{taskId}/test-binlog`

**功能**: 独立测试binlog监听器，验证是否能正常捕获binlog事件

**请求参数**:
```json
{
  "duration": 30  // 测试持续时间（秒），范围1-300
}
```

**使用方法**:
```bash
curl -X POST http://localhost:8080/api/v1/debug/incremental/{taskId}/test-binlog \
  -H "Content-Type: application/json" \
  -d '{"duration": 30}'
```

### 3. 获取增量同步状态

**接口**: `GET /api/v1/debug/incremental/{taskId}/status`

**功能**: 获取增量同步实例的详细状态信息

**使用方法**:
```bash
curl http://localhost:8080/api/v1/debug/incremental/{taskId}/status
```

**返回信息**:
- 队列大小
- 当前binlog位置
- 消费统计信息
- 任务状态
- 组件状态

## 常见问题诊断

### 问题1: 新增数据没有同步到目标库

**诊断步骤**:

1. **检查任务配置**
   ```bash
   curl -X POST http://localhost:8080/api/v1/debug/incremental/{taskId}/diagnose
   ```
   查看日志，确认：
   - 任务是否为增量同步模式
   - 源库和目标库配置是否正确
   - 选中的数据库和表是否包含你操作的表

2. **检查源库binlog配置**
   诊断会自动检查以下配置：
   - `log_bin` 是否开启
   - `binlog_format` 是否为 ROW
   - `binlog_row_image` 建议为 FULL

3. **测试binlog监听**
   ```bash
   curl -X POST http://localhost:8080/api/v1/debug/incremental/{taskId}/test-binlog \
     -H "Content-Type: application/json" \
     -d '{"duration": 60}'
   ```
   然后在源库执行一些INSERT/UPDATE/DELETE操作，查看日志是否有事件捕获

4. **检查增量同步状态**
   ```bash
   curl http://localhost:8080/api/v1/debug/incremental/{taskId}/status
   ```
   查看：
   - 队列大小是否在增长
   - 消费统计是否在更新
   - 各组件是否正常运行

### 问题2: binlog事件被捕获但没有应用到目标库

**可能原因**:
- 增量消费器没有启动
- 目标库连接失败
- 数据库/表名映射错误
- 字段过滤配置问题

**诊断方法**:
1. 查看增量同步状态，确认消费器是否活跃
2. 查看任务日志中的错误信息
3. 检查目标库是否可以正常连接

### 问题3: 队列积压严重

**可能原因**:
- 消费速度跟不上生产速度
- 目标库性能瓶颈
- 网络延迟

**诊断方法**:
1. 监控队列大小变化趋势
2. 查看消费统计中的失败事件数
3. 检查目标库的性能指标

## 日志查看

所有调试操作的详细信息都会记录在任务日志中：

**日志位置**: `logs/{taskId}/all.log`

**关键日志标识**:
- `[INFO]` - 正常信息
- `[WARNING]` - 警告信息  
- `[ERROR]` - 错误信息

**重要日志关键词**:
- `Binlog 监听器启动` - binlog监听器状态
- `INSERT事件已推送到队列` - 事件捕获
- `从队列获取到事件` - 事件消费
- `事件处理成功` - 事件应用成功

## 性能监控

### 关键指标

1. **队列大小** (`queue_size`)
   - 正常情况下应该保持在较低水平
   - 持续增长表示消费跟不上生产

2. **事件处理速度** (`events_processed`)
   - 监控每秒处理的事件数
   - 与源库的变更频率对比

3. **失败事件数** (`events_failed`)
   - 应该保持为0或很低的数值
   - 持续增长需要检查错误原因

### 监控建议

- 定期调用状态接口获取实时数据
- 设置告警阈值（如队列大小>1000）
- 监控日志中的ERROR级别消息

## 故障排除流程

1. **运行完整诊断**
   ```bash
   curl -X POST http://localhost:8080/api/v1/debug/incremental/{taskId}/diagnose
   ```

2. **查看诊断日志**
   检查 `logs/{taskId}/all.log` 中的诊断结果

3. **根据问题类型进行针对性测试**
   - binlog配置问题 → 修复源库配置
   - 监听器问题 → 运行binlog测试
   - 消费器问题 → 检查目标库连接

4. **持续监控状态**
   定期获取增量同步状态，观察指标变化

## 注意事项

1. **测试环境使用**: 建议先在测试环境验证调试功能
2. **性能影响**: 调试功能会产生额外的日志，注意磁盘空间
3. **并发限制**: 同一时间只运行一个binlog测试，避免冲突
4. **权限要求**: 确保源库用户具有REPLICATION SLAVE权限
