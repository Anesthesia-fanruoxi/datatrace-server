# 索引去重机制

## 文档说明

本文档描述 Elasticsearch 索引去重机制的设计（规划中）。

**文档版本**: v2.0
**最后更新**: 2026-07
**实现状态**: 规划中

---

## 问题场景

当配置多个同步任务时，可能出现多个任务同步到同一个 Elasticsearch 索引的情况，导致数据冲突。

---

## 设计思路

- 在创建任务时检测目标索引是否已被其他任务使用
- 如果检测到重复，提示用户确认或阻止创建
- 支持用户显式配置"允许重复"

---

## 当前状态

当前系统仅支持 MySQL → MySQL 同步，此机制暂未实现。
后续扩展 Elasticsearch 支持时将实现此功能。
# Elasticsearch 索引去重机制

## 📋 文档说明

本文档详细描述 DataTrace 系统针对 Elasticsearch 索引的去重机制，避免重复同步相同的索引。

**文档版本**: v2.0  
**最后更新**: 2026-02-27  
**技术栈**: Go + Gin + GORM  
**实现状态**: 设计阶段

---

## 🎯 问题场景

### 场景 1: 跨任务的索引重复

```
第一次同步任务:
- 关键字: "user"
- 匹配到索引: index-user-2024, index-user-2025
- 同步完成 ✅

第二次同步任务:
- 关键字: "user-data"
- 匹配到索引: index-user-2024, index-user-2025, index-user-data
- 问题: index-user-2024 和 index-user-2025 已经同步过了 ❌
- 需求: 只同步 index-user-data，跳过已同步的索引 ✅
```

### 场景 2: 单次任务内的索引重复

```
一次同步任务:
- 关键字1: "user"  → 匹配: index-user-2024, index-common
- 关键字2: "common" → 匹配: index-common, index-common-data
- 关键字3: "data"  → 匹配: index-common-data, index-data-2024

问题:
- index-common 在关键字1和2中都出现
- index-common-data 在关键字2和3中都出现

需求:
1. 去重: 每个索引只同步一次
2. 标签: 使用第一次出现的关键字作为标签
   - index-common → 标签: "user"
   - index-common-data → 标签: "common"
```

---

## 🏗️ 解决方案设计

### 两层去重机制

**第一层: 任务内去重（单次执行）**
- 时机: 创建任务单元时
- 范围: 当前任务的所有关键字
- 策略: 使用 map 去重
- 标签: 记录第一次出现的关键字

**第二层: 跨任务去重（历史记录）**
- 时机: 创建任务单元时
- 范围: 所有历史任务
- 策略: 查询 synced_indices 表
- 选项: 支持强制重新同步

---

## 🔧 数据模型设计

### 1. 任务配置扩展

```go
// 任务配置
type TaskConfig struct {
    // 原有字段
    Units      []string   `json:"units"`
    SyncConfig SyncConfig `json:"sync_config"`
    
    // 新增字段
    Keywords   []KeywordMapping `json:"keywords,omitempty"`   // 关键字映射
    SkipSynced bool             `json:"skip_synced"`          // 是否跳过已同步的索引（默认 true）
}

// 关键字映射
type KeywordMapping struct {
    Keyword string   `json:"keyword"` // 关键字
    Indices []string `json:"indices"` // 匹配到的索引列表
}
```

**JSON 示例**：
```json
{
  "units": [
    "index-user-2024",
    "index-common",
    "index-common-data",
    "index-data-2024"
  ],
  "keywords": [
    {
      "keyword": "user",
      "indices": ["index-user-2024", "index-common"]
    },
    {
      "keyword": "common",
      "indices": ["index-common", "index-common-data"]
    },
    {
      "keyword": "data",
      "indices": ["index-common-data", "index-data-2024"]
    }
  ],
  "skipSynced": true,
  "syncConfig": {
    "threadCount": 4,
    "batchSize": 5000
  }
}
```

### 2. 任务单元扩展

```go
// 任务单元配置
type TaskUnitConfig struct {
    ID        string    `gorm:"primaryKey;size:36" json:"id"`
    TaskID    string    `gorm:"size:36;not null" json:"task_id"`
    UnitName  string    `gorm:"size:200;not null" json:"unit_name"`
    UnitType  string    `gorm:"size:20;not null" json:"unit_type"`
    
    // 新增字段
    Keyword   string    `gorm:"size:100" json:"keyword"` // 关联的关键字（标签）
    
    CreatedAt time.Time `json:"created_at"`
}
```

### 3. 已同步索引表

```sql
-- 新增表: 记录已同步的索引
CREATE TABLE `synced_indices` (
    `id` VARCHAR(36) PRIMARY KEY COMMENT 'UUID主键',
    `source_id` VARCHAR(36) NOT NULL COMMENT '数据源ID',
    `index_name` VARCHAR(200) NOT NULL COMMENT '索引名称',
    `first_synced_at` DATETIME NOT NULL COMMENT '首次同步时间',
    `last_synced_at` DATETIME NOT NULL COMMENT '最后同步时间',
    `sync_count` INT DEFAULT 1 COMMENT '同步次数',
    `last_task_id` VARCHAR(36) COMMENT '最后同步的任务ID',
    UNIQUE KEY `uk_source_index` (`source_id`, `index_name`),
    INDEX `idx_source_id` (`source_id`),
    INDEX `idx_index_name` (`index_name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='已同步索引表';
```

## 🔄 执行流程

### 完整流程图

```
前端创建任务
   ├─ 用户选择关键字: ["user", "common", "data"]
   ├─ 前端查询 ES，获取每个关键字匹配的索引
   └─ 构建 keywords 映射
   ↓
后端接收任务配置
   ↓
TaskService.CreateTask()
   ↓
1. 任务内去重
   ├─ 遍历所有 keywords
   ├─ 使用 map[string]string 记录 (索引 → 关键字)
   ├─ 如果索引已存在，跳过（保留第一个关键字）
   └─ 得到去重后的索引列表
   ↓
2. 跨任务去重（如果 skipSynced = true）
   ├─ 查询 synced_indices 表
   ├─ 过滤掉已同步的索引
   └─ 得到最终需要同步的索引列表
   ↓
3. 创建任务单元
   ├─ 为每个索引创建 TaskUnitConfig
   ├─ 设置 keyword 字段（标签）
   └─ 保存到数据库 (GORM)
   ↓
4. 执行同步
   ├─ 正常执行同步流程
   └─ 每个单元完成后，记录到 synced_indices
```

---

## 💻 核心实现思路

### 1. 任务内去重

**实现要点**:
- 使用 `map[string]string` 存储索引到关键字的映射
- 遍历所有关键字映射，只保留第一次出现的索引
- 返回去重后的索引列表和对应的关键字

### 2. 跨任务去重

**实现要点**:
- 查询 `synced_indices` 表，检查索引是否已同步
- 如果 `skipSynced` 为 true，过滤掉已同步的索引
- 如果 `skipSynced` 为 false，保留所有索引（强制重新同步）

### 3. 记录已同步索引

**实现要点**:
- 任务单元完成后，调用记录方法
- 使用 `ON DUPLICATE KEY UPDATE` 或 GORM 的 `Save` 方法
- 更新同步次数和最后同步时间

## 📊 配置示例

### 示例 1: 启用跨任务去重（默认）

```json
{
  "units": [
    "index-user-2024",
    "index-common",
    "index-data-2024"
  ],
  "keywords": [
    {
      "keyword": "user",
      "indices": ["index-user-2024", "index-common"]
    },
    {
      "keyword": "data",
      "indices": ["index-common", "index-data-2024"]
    }
  ],
  "skipSynced": true,
  "syncConfig": {
    "threadCount": 3,
    "batchSize": 5000
  }
}
```

**执行结果**：
```
任务内去重:
- index-user-2024 (keyword: "user")
- index-common (keyword: "user") ← 保留第一个关键字
- index-data-2024 (keyword: "data")

跨任务去重:
- 检查 synced_indices 表
- 假设 index-user-2024 已同步，跳过
- 最终同步: index-common, index-data-2024
```

### 示例 2: 禁用跨任务去重（强制重新同步）

```json
{
  "units": ["index-user-2024"],
  "skipSynced": false,
  "syncConfig": {
    "threadCount": 1,
    "batchSize": 5000
  }
}
```

**执行结果**：
```
- 不检查 synced_indices 表
- 强制重新同步 index-user-2024
- 更新 synced_indices 表的 sync_count
```

## 🎯 使用场景

### 场景 1: 多关键字搜索

```
用户操作:
1. 输入关键字: "user", "common", "data"
2. 前端查询 ES，获取每个关键字的索引列表
3. 提交任务配置

后端处理:
1. 任务内去重: 每个索引只保留一次
2. 跨任务去重: 跳过已同步的索引
3. 创建任务单元，记录关键字标签
4. 执行同步
5. 完成后记录到 synced_indices
```

### 场景 2: 定期同步

```
场景: 每天同步新增的索引

第一天:
- 关键字: "log-2024"
- 匹配: log-2024-01-01, log-2024-01-02
- 同步完成，记录到 synced_indices

第二天:
- 关键字: "log-2024"
- 匹配: log-2024-01-01, log-2024-01-02, log-2024-01-03
- 跨任务去重: 跳过前两个
- 只同步: log-2024-01-03
```

### 场景 3: 强制重新同步

```
场景: 数据有问题，需要重新同步

操作:
- 设置 skipSynced = false
- 提交任务

结果:
- 不检查 synced_indices
- 强制重新同步所有索引
- 更新 synced_indices 的同步次数
```

## 🔍 管理功能

### 查询已同步索引

**API**: `GET /api/v1/datasources/:id/synced-indices`

**功能**: 获取指定数据源的已同步索引列表

### 清除同步历史

**API**: `DELETE /api/v1/datasources/:id/synced-indices/:indexName`

**功能**: 清除指定索引的同步历史

**API**: `DELETE /api/v1/datasources/:id/synced-indices`

**功能**: 清除数据源的所有同步历史
